# How to join in

You need a free GitHub account to leave feedback on the walkthrough. Setting it up takes about five minutes. You don't need to install anything or know Git.

## 1. Create a GitHub account

1. Go to [github.com/signup](https://github.com/signup).
2. Enter an e-mail address and a password.
3. Choose a **username that is not your real name** (for example a nickname plus a number). This repository is public, so your username will be visible next to your comments. Leave the "Name" field in your profile empty for the same reason.
4. Solve the check GitHub shows you and confirm your e-mail address with the code GitHub sends.
5. Choose the **Free** plan if GitHub asks.
6. Send your username to the repo owner through your team chat (not in a comment), so your feedback can be matched to "Member A–E" in the requirements file. Your username never appears in the project files.

## 2. Open the walkthrough

Open the walkthrough link from the team chat. It works on a laptop or phone. The table of contents on the left (at the top on phones) takes you to each section.

## 3. Leave feedback on a section

1. Read the section, including the code and output cells.
2. Scroll to the box under the section and select **Open the discussion**.
3. The first time, select **Sign in with GitHub** and allow giscus (the comment tool) to post for you. It only gets permission to write comments.
4. Write **one comment per point** and start it with one of these words, so the agent can sort it:
   - **Unclear:** what you did not understand. Example: "Unclear: why is the split by website and not random?"
   - **Change:** what you want changed, and why. Example: "Change: show the confusion matrix as percentages, the counts are hard to compare."
   - **Other:** anything else.
5. Select **Comment**.

You can reply to other people's comments to agree or discuss. Replies are collected too.

## 4. Sign off a section

When you understand a section and agree with it, react with 👍 on the discussion post at the top of the comment box (not on a comment). A cycle is finished when all five of us have given 👍 on every section and no comments are open.

## 5. What happens next

At the end of a feedback period, the repo owner collects all comments. They become a numbered requirements file for the next cycle, and conflicting requests are listed side by side for the team to decide. After the next overnight run, the walkthrough is updated and the next feedback period starts.

## If something doesn't work

- **The comment box says comments are not connected:** tell the repo owner; one setup step is missing.
- **You can't sign in:** check that you confirmed your e-mail address with GitHub.
- **You'd rather not use GitHub:** send your feedback to the repo owner, who will add it to the requirements as one of the five members.
